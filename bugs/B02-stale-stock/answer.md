# 注文後に在庫表示が更新されない

| 項目 | 内容 |
|---|---|
| レイヤー | フロントエンド |
| 難易度 | ★☆☆ |
| 推奨段階 | 基礎形成期 |
| 主に鍛える力 | 観測、切り分け |

## 原因

注文完了後に商品一覧を再取得する仕組みはありますが、再取得のきっかけになる状態の変化を監視していません。

| スタック | 該当箇所 | 仕込んだ変更 |
|---|---|---|
| React | `frontend/src/components/ShopPage.tsx` | `useEffect` の依存配列から `refreshKey` を削除 |
| Vue | `frontend/src/components/ShopPage.vue` | `watch` の監視対象から `refreshKey` を削除 |

`refreshKey` を増やす処理は残っているため、コードをざっと読むと再取得しているように見えます。

## 想定される調査の流れ

1. 注文後にDBの在庫数を確認し、DB上は正しく減っていることを確かめる。サーバーではなく画面側の問題だと切り分ける。
2. 開発者ツールのネットワークタブで、注文後に `GET /api/products` が呼ばれていないことを確認する。
3. 商品一覧を取得している箇所を読み、どの状態が変わったときに再取得されるのかを追う。

## 正しい修正

依存配列(React)または監視対象(Vue)に `refreshKey` を戻します。

## 再発防止の例

- React であれば、ESLint の `react-hooks/exhaustive-deps` ルールを導入する。
- 「操作のあとに画面のどのデータが変わるべきか」を、画面ごとに確認するテストを書く。

## 指導のポイント

- 「DBは正しいか」を最初に確認できたかを見ます。フロントとバックエンドのどちらの問題かを切り分ける、最も基本的な一手です。
- React や Vue の再描画・再取得の仕組みを、自分の言葉で説明できるかを問いかけてください。フレームワークのメンタルモデルを確認する良い機会になります。

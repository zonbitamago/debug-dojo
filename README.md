# debug-dojo(デバッグ演習 管理用リポジトリ)

若手エンジニア向けのデバッグ演習で使う、練習用ECショップと、そこに仕込むバグを管理するリポジトリです。「AI時代の若手エンジニア教育」資料の原則2(デバッグを教育の中核に置く)の「バグを仕込んだアプリで練習する」に対応しています。

**このリポジトリには演習の答えが含まれています。シニア(指導担当)だけが閲覧できるプライベートリポジトリで管理してください。** 若手には、ここから生成した演習用リポジトリだけを渡します。

## 仕組み

```
debug-dojo(このリポジトリ・シニアのみ)          演習用リポジトリ(若手に渡す)
├─ 正解版のアプリ(3スタック)                    ├─ 選んだバグだけを仕込んだアプリ
├─ バグごとのパッチ・チケット・解説   ──生成──▶   ├─ チケット(症状の報告のみ)
└─ 生成スクリプト                                └─ 調査ログのテンプレート
```

演習用リポジトリは、選んだバグを適用した状態で、履歴なしの1コミットとして生成されます。バグのIDやタイトル、仕込んだ差分は演習用リポジトリには一切含まれません。チケットも並び順をシャッフルし、「チケット-1」のような名前で配置します。

## 対応スタック

| スタック名 | フロントエンド | バックエンド | DB |
|---|---|---|---|
| `node-react` | React + TypeScript | Node.js + Express + TypeScript | PostgreSQL 16 |
| `rails-vue` | Vue 3 + TypeScript | Ruby on Rails 7.2(API) | PostgreSQL 16 |
| `java-react` | React + TypeScript | Java 21 + Spring Boot 3 | PostgreSQL 16 |

題材はすべて同じECサイトの注文機能で、DB、決済代行のモック、画面の仕様、バグの症状も共通です。若手が普段触る技術に近いスタックを選んでください。

## バグ一覧

| ID | 内容 | レイヤー | 難易度 | 推奨段階 |
|---|---|---|---|---|
| B01 | 二重送信による二重注文 | フロントエンド | ★☆☆ | 基礎形成期 |
| B02 | 注文後に在庫表示が更新されない | フロントエンド | ★☆☆ | 基礎形成期 |
| B03 | 注文履歴の N+1 クエリ | バックエンド | ★★☆ | 基礎形成期の後半〜 |
| B04 | 在庫の確保がトランザクションの外 | バックエンド | ★★★ | 補助生成期〜 |
| B05 | 日別集計のタイムゾーンの誤り | バックエンド(SQL) | ★★☆ | 補助生成期 |
| B06 | 注文番号のインデックスがない | DB | ★★☆ | 基礎形成期の後半〜 |
| B07 | 決済APIのタイムアウト設定が効いていない | 設定・外部連携 | ★★★ | 補助生成期 |
| B08 | 在庫の更新で競合状態が起きている | 並行処理 | ★★★ | 委任期 |

各バグのフォルダ(`bugs/Bxx-*/`)には、次のファイルがあります。

| ファイル | 内容 | 若手に渡すか |
|---|---|---|
| `symptom.md` | チケット(利用者や社内からの報告という体裁の症状説明) | 渡す(生成時に自動でコピー) |
| `answer.md` | 原因、想定される調査の流れ、正しい修正、指導のポイント | 渡さない |
| `patches/<stack>.patch` | 正解版にバグを仕込む差分 | 渡さない |

## 使い方

必要なもの:bash、patch、git(演習の実行には Docker と Docker Compose)

### バグの一覧を見る

```bash
scripts/new-exercise.sh --list
```

### 演習用リポジトリを生成する

```bash
scripts/new-exercise.sh -s node-react -b B01,B03,B06 -o ../exercise-2026-04-tanaka
```

`-b all` ですべてのバグを仕込めます。実行すると、どのチケットがどのバグに対応するか(出題記録)が表示されます。**これは若手に見せないよう、指導担当の手元で控えてください。**

生成したディレクトリを、若手用の新しいリポジトリとして push します。

```bash
cd ../exercise-2026-04-tanaka
git remote add origin git@github.com:<org>/exercise-2026-04-tanaka.git
git push -u origin main
```

### 正解版を動かす

```bash
scripts/assemble.sh node-react ../shop-clean
cd ../shop-clean && docker compose up --build
```

### パッチが壊れていないか確認する

正解版のコードを変更したときは、必ず実行してください。すべてのバグが、単独でも全部同時でも適用できるかを確認します。

```bash
scripts/verify-patches.sh
```

### 正解版のコードを変更したとき

`python3 tools/build_patches.py` で全バグのパッチを再生成し、`scripts/verify-patches.sh` で確認します。パッチは手で編集せず、`tools/bug_edits.py` の置換定義を直してください。

### 新しいバグを追加する

1. `bugs/B09-xxx/` を作り、`symptom.md` と `answer.md` を書く(既存のバグを参考にしてください)。
2. 正解版を組み立てて、バグを仕込む。

   ```bash
   scripts/assemble.sh node-react /tmp/work
   # /tmp/work のコードを編集してバグを仕込む
   ```

3. パッチを作る。

   ```bash
   mkdir -p bugs/B09-xxx/patches
   scripts/make-patch.sh node-react /tmp/work > bugs/B09-xxx/patches/node-react.patch
   ```

4. 他のスタックにも同じ手順でパッチを作る。DB のみの変更など、全スタック共通の差分は `common.patch` という名前にすると、すべてのスタックで使われます。
5. `scripts/verify-patches.sh` で、既存のバグと競合しないことを確認する。

## ディレクトリ構成

```
.
├── bugs/                 バグごとのチケット・解説・パッチ
├── docs/運用ガイド.md     演習の進め方、出題の組み方、振り返りの観点
├── tools/                全バグのパッチを一括で再生成するスクリプトと、各バグの置換定義
├── scripts/
│   ├── new-exercise.sh   演習用リポジトリの生成
│   ├── assemble.sh       正解版の組み立て
│   ├── make-patch.sh     バグのパッチ作成
│   └── verify-patches.sh パッチの検証
├── shared/
│   ├── db/init.sql       テーブル定義と初期データ(注文300万件)
│   ├── payment-mock/     決済代行サービスのモック
│   ├── frontend-react/   React の画面(node-react / java-react で共用)
│   ├── frontend-vue/     Vue の画面(rails-vue で使用)
│   └── exercise-kit/     演習用リポジトリの README と調査ログのテンプレート
└── stacks/
    ├── node-react/       Node.js のバックエンドと docker-compose.yml
    ├── rails-vue/        Rails のバックエンドと docker-compose.yml
    └── java-react/       Spring Boot のバックエンドと docker-compose.yml
```

## 動作確認の状況

作成時点で、次の範囲を確認しています。Rails 版と Java 版は、作成環境からライブラリを取得できなかったため実行による確認ができていません。**最初に使う前に、指導担当が一度 `docker compose up --build` で起動し、正解版が動くことと、各バグの症状が出ることを確認してください。** 確認の手順は各バグの `answer.md` の「想定される調査の流れ」が参考になります。

| 確認項目 | node-react | rails-vue | java-react |
|---|---|---|---|
| 全パッチの単独適用・同時適用 | 確認済み | 確認済み | 確認済み |
| フロントエンドのビルド | 確認済み | 確認済み | 確認済み(React は共通) |
| ブラウザでの B01・B02 の症状再現 | 確認済み | 確認済み(Vue 画面) | 確認済み(React は共通) |
| バックエンドの構文チェック | 確認済み | 確認済み(`ruby -c`) | 確認済み(スタブによる型チェックまで) |
| 正解版の動作(API・DB を使った実行) | 確認済み | 未確認 | 未確認 |
| B03〜B08 の症状再現(実行) | 確認済み | 未確認 | 未確認 |
| Docker での起動 | 未確認 | 未確認 | 未確認 |

node-react 版の主な確認結果(正解版 → バグあり)は次のとおりです。

| バグ | 正解版 | バグあり |
|---|---|---|
| B03 | 佐藤さんの注文履歴 11〜37ms | 452ms(クエリ 1,201回) |
| B04 | 与信上限エラー後も在庫 80 のまま | 在庫 80 → 78 |
| B05 | 当日の件数が日本時間の集計と一致 | 当日分が大きく減る(確認時は約4分の1) |
| B06 | 注文番号検索 3ms | 約210ms(全件走査) |
| B07 | 1万円超の注文が成功 | 約1秒でエラー、決済代行側では承認済み |
| B08 | 15件同時注文で成立10件・在庫0 | 成立15件・在庫9 |
